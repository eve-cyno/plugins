Getting started

Node 22 or newerPlugin API 1.29.0Local only for now

Create a plugin from the template, build it and load it in the desktop app. About five minutes, no account and no permission request.

On this page
  • Before you start
  • Create, build, load

  • Next steps
Ask on DiscordBack to top

Before you start#

You need Node 22 or newer, npm, and the EVE-Cyno desktop app with Settings > Plugins > Developer available. A plugin is a folder with a plugin.json, one HTML page and a script. It runs in a sandbox and reaches the app only through the plugin API.

Nobody can install your plugin yet

The Marketplace is not live. A plugin you build here runs on your machine, from a folder you chose. You cannot publish it, and no one else can find it. Build it anyway: the same folder is what you will submit.

Create, build, load#

  1. Create the project 
    npm create @eve-cyno/plugin my-plugin
  2. Build it 
    cd my-plugin && npm run build
  3. Load the folder

    In the app open Settings > Plugins > Developer, switch the developer folder on and pick dist/<your-id>. The app reloads the plugin each time the build changes it.

What you get#

The template asks for no permission, which is the smallest thing a reviewer can read. One command and one tile action show where contributes goes.

my-plugin/
  plugin.json
  package.json
  tsconfig.json
  src/main.ts
  static/main.html
  static/style.css
  scripts/build.mjs
  scripts/archive.mjs
  entry/dev.example.my-plugin.json
  types/eve-cyno-plugin-api/index.d.ts
{
  "id": "dev.example.my-plugin",
  "name": "My Plugin",
  "version": "0.1.0",
  "engines": { "eve-cyno-api": "^1.29" },
  "main": "main.html",
  "activationEvents": ["onStartup"],
  "permissions": {}
}
import type { EveCyno } from '@eve-cyno/plugin-api';

const eveCyno = (globalThis as { eveCyno: EveCyno }).eveCyno;

eveCyno.commands.onCommand((command) => {
  // the user ran one of this plugin's commands
  if (command.id === 'hello') eveCyno.tile.setSummary({ title: 'Hello' });
});

Generated at build time from the template, so these tabs always match what npm create writes.

storage

always presentpermissions.storage

A small key-value store that belongs to your plugin. Values survive restarts and are written to disk within 250 ms.

On this page
  • Declaration
  • Methods
  • Limits and errors
Ask on DiscordBack to top

Declaration#

Get the namespace from getEveCyno(). Every method returns a promise.

StorageNamespace · api/1.29.0.d.ts
export interface StorageNamespace {
    get(params: { key: string; }): Promise<unknown>;
    set(params: { key: string; value: unknown; }): Promise<true>;
    delete(params: { key: string; }): Promise<boolean>;
    keys(): Promise<string[]>;
}

Methods#

MethodReturnsWhat it does
getPromise<unknown>Reads one value. A key that was never set reads as undefined.
setPromise<true>Writes one value. Resolves once the write is in memory.
deletePromise<boolean>Removes a key. Resolves true when the key existed.
keysPromise<string[]>Lists every key your plugin has stored.
src/main.ts
const { storage } = getEveCyno();
await storage.set({ key: 'lastTab', value: 'ledger' });
const tab = await storage.get({ key: 'lastTab' }); // 'ledger'

Limits and errors#

  • A value may nest at most 64 levels deep. An own __proto__ key is refused with bad_params.
  • A crash can lose the last 250 ms of writes. The host flushes at once when the plugin unloads or the app quits.
  • unavailable means the file is locked or the disk refused the write. Reads keep working and writes resume after a retry.

Call budget

All pages of one plugin share 100 calls, refilled at 100 a second. A call past it fails with rate_limited before it runs, so the same call may go again after a short wait.

plugin.json

schema manifest.v15 required

The manifest names your plugin, says which API it needs and lists every permission it asks for. The app refuses a plugin whose manifest breaks a rule below.

Properties#

Fifteen top-level properties. The table is generated from the schema, one row per property.

PropertyTypeNotes
idrequiredstringReverse-domain style, unique. The prefix eve-cyno.host. is reserved.
namerequiredstringShown in Settings > Plugins. Plain text only.
versionrequiredstringSemantic version, for example 0.1.0.
enginesrequiredobject{ "eve-cyno-api": "^1.29" }. The app refuses with incompatible_api when it is older.
mainrequiredstringPath of the page the app loads, inside the plugin folder.
authorstringShown next to the name.
descriptionstringOne or two sentences for the plugin list.
iconstringA lowercase name, 1 to 24 letters.
colorstringAccent colour of the tile.
activationEventsarrayWhen the plugin starts, for example onStartup.
backgroundbooleanKeep running when its window is closed.
suspendUnderPressurebooleanLet the app pause a background plugin when the machine is under load.
esiCompatibilityDatestringThe ESI compatibility date the plugin was written against.
permissionsobjectTwenty keys. See Permissions and grants.
contributesobjectCommands, settings, tile actions and other things the plugin adds to the app.

Accepted and refused#

Each example on this page runs through the app's own manifest parser when the docs are built. A block marked accept must pass, and a block marked refuse must throw the code it names.

  "version": "0.1.0",
  "engines": { "eve-cyno-api": "^2.0" },
  "main": "main.html"
}

Optional permissions#

A permission listed under permissions.optional is asked for at run time, after the user has used the plugin. It needs eve-cyno-api ^1.17 or newer.

Needs engines
^1.17 or newer
Asked
When the plugin calls permissions.request, from one user gesture
Refused
The call resolves 'declined'; the plugin keeps working without it

Ask for less

A plugin with an empty permissions object is the quickest to review. Add a permission when a feature needs it, not before.
